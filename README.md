# DevOps-trainee

Задача 1. Поднять веб-сервер и отдать статику

Что делает DevOps: Настраивает сервер, который отдает сайт.

Что сделать:

    Установить Nginx на локальную машину (или в контейнере).

    Создать простую HTML-страницу index.html с текстом "Hello, DevOps!".

    Настроить Nginx так, чтобы он отдавал эту страницу на порту 8080.

    Проверить через браузер: http://localhost:8080

Проверка: curl http://localhost:8080 возвращает вашу страницу.
bash

# Подсказка (через Docker)
docker run -d -p 8080:80 -v $(pwd)/html:/usr/share/nginx/html nginx:alpine

## Задача 2. Настроить reverse proxy с двумя бэкендами

Что делает DevOps: Проксирует запросы на разные внутренние сервисы.

Что сделать:

    Запустить два контейнера с разными приложениями:

        Контейнер A: httpd (Apache) на порту 8081, отдает "App A"

        Контейнер B: nginx на порту 8082, отдает "App B"

    Настроить основной Nginx (на хосте или отдельным контейнером) так:

        /app1 → контейнер A

        /app2 → контейнер B

    Проверить, что localhost/app1 и localhost/app2 показывают разное.

Проверка: curl localhost/app1 и curl localhost/app2 возвращают разные ответы.
## Задача 3. Написать Dockerfile для Node.js приложения

Что делает DevOps: Упаковывает приложение в образ для воспроизводимого деплоя.

Что сделать:

    Создать простейшее Node.js приложение (файл server.js):
    javascript

    const http = require('http');
    http.createServer((req, res) => res.end('Hello from Node')).listen(3000);

    Написать Dockerfile, который:

        Использует официальный образ Node

        Копирует код

        Устанавливает зависимости (если бы они были)

        Запускает приложение

    Собрать образ: docker build -t my-node-app .

    Запустить контейнер на порту 3000.

Проверка: curl localhost:3000 → "Hello from Node"
## Задача 4. Написать docker-compose для связки App + Postgres

Что делает DevOps: Поднимает многоконтейнерное окружение одной командой.

Что сделать:

    Создать docker-compose.yml с двумя сервисами:

        app: ваше Node.js приложение (из задачи 3)

        db: PostgreSQL

    Настроить переменные окружения для PostgreSQL (POSTGRES_USER, POSTGRES_PASSWORD, POSTGRES_DB)

    Настроить сеть между контейнерами, чтобы приложение видело БД по имени db

    Запустить: docker-compose up -d

Проверка: Приложение должно подключаться к БД (даже если не использует — просто проверьте, что контейнеры видят друг друга через docker exec app ping db)
## Задача 5. Написать скрипт бэкапа с ротацией

Что делает DevOps: Автоматизирует рутину и чистит старые файлы.

Что сделать:

    Написать bash-скрипт backup.sh, который:

        Создает архив backup_$(date +%Y%m%d).tar.gz из папки ~/data

        Кладет архив в ~/backups

        Удаляет архивы старше 7 дней (find + mtime)

    Создать тестовую папку ~/data с несколькими файлами.

    Запустить скрипт вручную, проверить.

Проверка: ls ~/backups — появился архив. Запустить дважды — старый архив удалится через 7 дней или при повторном запуске с флагом очистки.
## Задача 6. Настроить мониторинг через Prometheus + Grafana

Что делает DevOps: Визуализирует состояние системы.

Что сделать:

    Запустить через docker-compose три сервиса:

        prometheus (сбор метрик)

        grafana (дашборды)

        node-exporter (сбор метрик с хоста)

    Настроить Prometheus: prometheus.yml с таргетом node-exporter:9100

    Зайти в Grafana (порт 3000, admin/admin), добавить источник данных Prometheus.

    Построить график загрузки CPU.

Проверка: В Grafana виден график загрузки вашего компьютера.
yaml

# Ключевой фрагмент prometheus.yml
scrape_configs:
  - job_name: 'node'
    static_configs:
      - targets: ['node-exporter:9100']

## Задача 7. Собрать инфраструктуру через Terraform (локально)

Что делает DevOps: Описывает инфраструктуру кодом (IaC).

Что сделать:

    Установить Terraform.

    Написать main.tf, который создает:

        Docker-контейнер с Nginx (провайдер kreuzwerker/docker)

        (Или для начала просто файл hello.txt через local_file ресурс)

    Выполнить terraform init, terraform plan, terraform apply

    Уничтожить: terraform destroy

Проверка: После apply появляется контейнер или файл. После destroy — исчезает.
hcl

# Пример с файлом
resource "local_file" "example" {
  content  = "Hello from Terraform"
  filename = "${path.module}/hello.txt"
}

## Задача 8. Настроить CI/CD пайплайн в GitLab CI (или GitHub Actions)

Что делает DevOps: Автоматизирует сборку и тестирование при каждом push.

Что сделать:

    Зарегистрироваться на gitlab.com (бесплатно).

    Создать репозиторий, залить туда ваш Node.js проект (из задачи 3).

    Создать файл .gitlab-ci.yml:
    yaml

    stages:
      - build
      - test

    build:
      stage: build
      script:
        - docker build -t myapp .
        - echo "Build complete"

    test:
      stage: test
      script:
        - echo "Running tests..."
        - node -e "console.log('Tests passed')"

    Запушить — убедиться, что пайплайн прошел зеленым.

Проверка: В GitLab в разделе CI/CD виден успешный пайплайн.
## Задача 9. Написать скрипт healthcheck для сервисов

Что делает DevOps: Автоматически проверяет, что всё работает.

Что сделать:

    Запустить docker-compose с nginx и postgres.

    Написать скрипт healthcheck.sh, который:

        Проверяет, отвечает ли Nginx на localhost:80 (curl -f)

        Проверяет, доступна ли PostgreSQL (pg_isready или nc -z localhost 5432)

        Если что-то не отвечает — выводит сообщение и выходит с кодом ошибки (1).

    Запустить скрипт, убедиться, что все OK.

    Остановить один сервис (docker stop), запустить скрипт снова — должен упасть.

Проверка: Скрипт возвращает 0 только когда оба сервиса живы.
## Задача 10. Развернуть приложение с нуля через Ansible (локально)

Что делает DevOps: Управляет конфигурацией серверов кодом.

Что сделать:

    Установить Ansible.

    Написать плейбук playbook.yml, который на localhost:

        Устанавливает Docker (если не установлен)

        Запускает контейнер с вашим Node.js приложением

        Убеждается, что контейнер запущен и слушает порт

    Запустить: ansible-playbook playbook.yml -c local

Проверка: После выполнения плейбука приложение доступно на порту 3000. Запустите плейбук второй раз — он должен сказать "ok", а не менять ничего лишнего (идемпотентность).
yaml

# Фрагмент плейбука
- name: Deploy my app
  hosts: localhost
  tasks:
    - name: Run container
      docker_container:
        name: myapp
        image: my-node-app:latest
        ports:
          - "3000:3000"
